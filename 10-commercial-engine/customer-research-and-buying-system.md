# 客户研究与购买决策系统

## 1. 目标

客户研究不是“画一个用户画像”，而是回答：**谁有问题、问题多严重、谁使用、谁影响、谁决策、谁付款、谁会阻止交易，以及客户为什么现在必须改变。**

## 2. 客户层级

```text
Market 市场
→ Industry 行业
→ Account 企业/组织
→ Segment 客户分层
→ Department 部门
→ Role 角色
→ Person 具体联系人
```

B2C 更关注消费者场景、动机、价格敏感度和渠道；B2B 则必须进一步识别组织结构、预算、采购流程和决策委员会。

## 3. ICP：Ideal Customer Profile

ICP 用于回答“哪类公司最值得卖”。至少包含：

| 维度 | 典型内容 |
|---|---|
| Firmographic | 行业、规模、收入、员工、地区、所有制 |
| Technographic | 现有系统、设备、云/AI成熟度、接口能力 |
| Operational | 流程复杂度、交易量、工厂/门店/团队数量 |
| Pain | 成本、效率、质量、增长、合规、风险 |
| Economics | 预算规模、ROI空间、采购能力 |
| Trigger | 扩张、换系统、政策变化、事故、成本上升、融资 |
| Fit | 产品能力、交付范围、国家、语言、认证、服务能力 |

### ICP 评分示例

```text
ICP Score = 需求强度 × 价值空间 × 购买能力 × 交付匹配 × 进入时机
```

不要求使用复杂公式，但必须显式说明为什么某类客户优先。

## 4. Persona 与角色分工

Persona 不是年龄和兴趣标签，而是工作目标、任务、约束和成功标准。

每个角色至少记录：

- Job：他要完成什么工作；
- KPI：什么结果决定他成功；
- Pain：什么阻碍结果；
- Current Solution：现在怎么解决；
- Objection：为什么不愿换；
- Value：什么价值最打动他；
- Evidence：需要什么证据才相信；
- Channel：通过什么渠道接触。

## 5. JTBD：Jobs To Be Done

把需求从“想要某功能”提升为“客户雇佣产品完成什么进步”。

推荐结构：

> 当我处于【情境】时，我想要【完成某项进步】，从而【获得业务/生活结果】。

JTBD 同时考虑：

- Functional Job：完成任务；
- Emotional Job：降低焦虑、增强控制感；
- Social Job：在组织或社交环境中获得认可。

## 6. VoC：Voice of Customer

证据来源优先级：

1. 真实客户访谈与销售录音；
2. 客诉、工单、退货和实施记录；
3. 平台评论、论坛和社媒讨论；
4. CRM 输单原因；
5. 竞品评价与案例；
6. 搜索、广告和行为数据。

VoC 应沉淀为：原话、问题、频率、严重度、触发场景、当前替代方案、愿付价值和证据来源。

## 7. DMU：Decision Making Unit

复杂 B2B 交易通常不是一个人决定。

| 角色 | 关注点 |
|---|---|
| User 使用者 | 易用性、效率、稳定性 |
| Champion 内部推动者 | 项目成功、个人影响力、可证明收益 |
| Economic Buyer 经济买家 | ROI、预算、风险、战略价值 |
| Technical Buyer | 架构、集成、安全、性能、运维 |
| Procurement 采购 | 价格、条款、供应商资质、比价 |
| Finance 财务 | 预算、付款、资本化/费用化、现金流 |
| Legal 法务 | 责任、IP、数据、违约、辖区 |
| Security/Compliance | 数据、隐私、认证、审计 |
| Blocker 阻碍者 | 权益受损、替代方案、组织政治 |

## 8. Buying Journey：购买旅程

```text
问题未被重视
→ 问题被确认
→ 内部形成需求
→ 搜索替代方案
→ 建立 shortlist
→ 技术/业务验证
→ 商务比较
→ 审批采购
→ 合同签署
→ 上线交付
→ 采用与扩张
```

销售必须判断客户处于哪个阶段，而不是所有客户都用同一种话术。

## 9. Discovery 访谈框架

推荐按照：

```text
现状 → 目标 → 问题 → 影响 → 原因 → 替代方案 → 优先级 → 决策 → 预算 → 时间
```

关键问题包括：

- 现在流程怎么做？
- 最近一次问题发生在什么时候？
- 造成了多少时间、成本、收入或风险损失？
- 为什么过去没有解决？
- 如果继续不解决会怎样？
- 谁最在意这个结果？
- 谁拥有预算？
- 采购必须经过哪些步骤？
- 什么时间点必须上线？

不要把访谈变成产品推销。

## 10. 客户价值量化

价值通常来自五类：

- Revenue：提高收入、转化、客单或产能；
- Cost：降低人工、广告、库存、能耗、运维成本；
- Risk：降低事故、违规、停机、质量和供应风险；
- Time：缩短交付、决策、上线或生产周期；
- Experience：提高客户、员工、合作伙伴体验。

价值量化为后续定价提供上限参考。

## 11. 客户研究输出物

一个可执行客户研究至少形成：

- ICP 定义与评分卡；
- 关键 Persona；
- DMU / Stakeholder Map；
- JTBD 清单；
- Pain / Gain / Trigger；
- Current Alternatives；
- Buying Journey；
- Objection Library；
- VoC Evidence Library；
- Discovery Guide；
- Win/Loss 复盘。

## 12. AI 应用

AI 可以用于访谈转写、VoC 聚类、角色识别、需求归因、相似客户匹配和输单原因分析，但不得凭空生成“客户事实”。所有重要结论应保留来源、时间、客户类型和置信度。
