# 产品系统与产品矩阵地图

## 1. 产品不只是 SKU

知识库统一把 Product 拆成三层：

```text
Physical Product 实体产品
+ Digital Product 数字产品
+ Service Product 服务产品
```

对于智能硬件、工业设备和企业软件，这三层往往共同决定客户价值和利润。

## 2. 产品系统示例

### 智能硬件

```text
设备本体
+ App
+ 固件
+ 云平台
+ AI能力
+ 配件/耗材
+ 安装/培训
+ 售后/延保
```

### B2B 软件

```text
Core Platform
+ 行业模块
+ API/集成
+ 数据/AI
+ 实施
+ 培训
+ 运维/SLA
+ 顾问服务
```

## 3. 产品矩阵的五个维度

- Customer：SMB / Mid-market / Enterprise，入门/专业/家庭等；
- Scenario：不同任务和使用环境；
- Price Tier：入门、中端、高端、旗舰；
- Capability：基础、标准、高配、行业版；
- Lifecycle：引流、增长、利润、形象、复购、淘汰。

## 4. 产品角色

| 角色 | 目的 |
|---|---|
| Acquisition | 拉新/降低首次购买门槛 |
| Hero | 形成规模与品牌认知 |
| Profit | 提升毛利与贡献利润 |
| Premium | 建立技术/品牌上限 |
| Retention | 提高持续使用和留存 |
| Expansion | 增购、交叉销售 |
| Consumable | 形成高频复购 |
| Service | 降低风险并创造持续收入 |

## 5. 产品线经营

产品负责人不能只看功能 Roadmap，还要看：

- Revenue by Product；
- Gross Margin；
- Contribution Margin；
- Attach Rate；
- Upgrade Rate；
- Cross-sell；
- Churn/Replacement；
- Warranty Cost；
- Inventory；
- R&D Investment；
- 生命周期。

## 6. Good-Better-Best

一种常见包装结构：

```text
Good：完成核心任务
Better：提高效率、自动化与体验
Best：高级能力、治理、性能、服务与品牌价值
```

版本差异应围绕客户价值，不应仅通过人为砍功能制造升级压力。

## 7. Platform + Modules

当产品复杂度增加，可以从单体 SKU 演进为：

```text
平台核心
├── 场景模块
├── 行业模块
├── AI模块
├── 数据模块
├── 集成/API
└── 服务包
```

适合企业软件、工业平台和多产品智能硬件生态。

## 8. Hardware + Recurring Revenue

智能硬件常见长期结构：

```text
一次性设备
→ 配件/耗材
→ 云/会员
→ AI功能
→ 延保/维修
→ 企业管理平台
```

但 recurring revenue 必须建立在客户持续价值上，不能为了订阅而订阅。

## 9. Product Portfolio

组合层需要判断：

- 哪些产品共享供应链；
- 哪些共享客户；
- 哪些共享渠道；
- 哪些共享数据/平台；
- 哪些互相蚕食；
- 哪些形成交叉销售；
- 哪些应该退出。

## 10. 产品立项 Gate

```text
市场机会
→ 客户证据
→ 价值假设
→ 产品方案
→ 商业模式
→ 成本/定价
→ 渠道/GTM
→ 供应链/交付
→ 财务模型
→ Go / Test / No-Go
```

产品立项不应只通过 PRD 评审。

## 11. 生命周期

```text
探索
→ MVP
→ PMF验证
→ 成长
→ 规模化
→ 成熟
→ 优化利润
→ 升级/迁移/淘汰
```

不同阶段关注指标不同，不能用成熟产品的收入要求否定探索产品，也不能用“创新”掩盖长期不赚钱的产品。

## 12. 产品系统与 AI

AI 可以成为：

- 产品中的功能；
- 独立付费模块；
- 内部经营工具；
- 客户服务能力；
- 数据/决策平台。

必须区分“AI 是卖点”与“AI 真正改善业务指标”。
