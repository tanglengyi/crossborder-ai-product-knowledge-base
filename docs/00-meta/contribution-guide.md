# 贡献与维护规范

## 1. 新增内容前先判断类型

| 类型 | 适用内容 | 使用模板 |
|---|---|---|
| 主题 | 概念、能力模型、方法论、指标体系 | `topic-template.md` |
| 流程 | 有明确起点、步骤、角色和输出的业务流程 | `process-template.md` |
| 案例 | 真实项目、公司、商品、活动或复盘 | `case-template.md` |

## 2. 文件命名

- 目录和文件统一使用小写英文与连字符，例如 `market-intelligence.md`。
- 中文标题写在文件一级标题中。
- 不使用“最终版”“最新版”“新建文档”等不可维护名称。
- 同一主题不要按日期反复新建文件，应优先更新原文件并记录变更。

## 3. 文档结构

每篇主题文档优先包含：

1. 定义与边界
2. 业务目标
3. 核心对象
4. 关键流程
5. 角色与职责
6. 指标体系
7. 系统能力
8. AI 应用
9. 风险与常见误区
10. 关联知识

不要求所有章节都存在，但不能只堆砌名词。

## 4. 内容写法

- 先讲业务问题，再讲工具和系统。
- 区分战略、经营、执行和支撑层，不把不同层级混为一谈。
- 指标必须给出定义，必要时补充公式与统计口径。
- 流程必须写明输入、输出、责任人和异常分支。
- 产品能力必须说明服务对象、使用场景和产生的业务价值。
- AI 能力必须说明输入数据、模型动作、人工确认点和失败兜底。

## 5. 交叉引用

优先使用相对链接：

```markdown
参见 [数据分析与财务经营](../06-data-finance/data-and-finance.md)。
```

同一知识不要复制到多个文件。主文档负责定义，其他文档只描述本场景中的应用。

## 6. 案例证据等级

案例内容应标注信息性质：

- **事实**：有数据、平台记录、合同、报告或公开来源支持。
- **业务判断**：基于事实进行的解释。
- **假设**：尚未验证，需要实验或调研。
- **建议**：面向后续行动的方案。

## 7. 指标登记格式

新增指标建议使用以下字段：

| 字段 | 示例 |
|---|---|
| 指标名称 | 库存周转天数 DOH |
| 定义 | 当前库存可支持销售的天数 |
| 公式 | 可售库存 ÷ 日均销量 |
| 统计粒度 | SKU / 仓库 / 国家 |
| 更新频率 | 每日 |
| 数据源 | ERP、WMS、OMS |
| 责任角色 | 库存运营 |
| 预警规则 | 高于目标值或低于安全天数 |

## 8. 维护机制

- 每月检查失效链接、重复内容和术语冲突。
- 每季度更新平台政策、工具能力和行业数据。
- 核心方法论变更时，同步检查所有引用文件。
- 过时内容不直接删除，可在文首标记状态并说明替代文档。

建议状态：`草稿`、`验证中`、`已验证`、`已过时`。
