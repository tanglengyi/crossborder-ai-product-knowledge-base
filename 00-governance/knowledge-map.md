# 知识地图

## 1. 总体架构

```text
跨境电商经营知识库
├── 战略：市场 / 品类 / 品牌 / 财务
├── 经营：商品 / 流量 / 库存 / 客户 / 利润
├── 执行：采购 / 内容 / 广告 / 销售 / 物流 / 客服
├── 支撑：数据 / 财务 / 系统 / 项目 / 组织
└── 智能：数据平台 / AI平台 / 智能体 / 决策辅助
```

## 2. 业务主链路

```text
市场洞察
→ 品类选择
→ 商品企划
→ 产品开发
→ 供应商与采购
→ 生产与备货
→ 店铺与内容准备
→ 达人和广告获客
→ 销售转化
→ 履约交付
→ 售后与客户运营
→ 数据与财务复盘
→ 策略调整
```

## 3. 五类核心经营对象

### 商品

管理 SKU 角色、生命周期、价格、成本、销量、毛利和组合关系。

### 流量

管理渠道、内容、达人、广告、人群、CAC、转化率和自然流量占比。

### 库存

管理需求预测、补货、安全库存、在途、海外仓、断货和呆滞库存。

### 客户

管理获客、成交、服务、留存、复购、会员、评价、NPS 和 LTV。

### 资金

管理预算、成本、毛利、贡献利润、现金占用、库存资金和经营回报。

## 4. 知识实体及关系

| 实体 | 典型关系 |
|---|---|
| 市场 | 包含品类、国家、平台、用户和竞争者 |
| 品类 | 包含价格带、商品矩阵和目标人群 |
| SKU | 属于品类，由供应商生产，在渠道销售 |
| 供应商 | 提供商品、报价、MOQ、交期和质量能力 |
| 渠道 | 获得流量、产生订单、收取佣金 |
| 达人/素材 | 连接商品与流量，影响点击和转化 |
| 客户 | 产生订单、评价、售后、复购和推荐 |
| 订单 | 连接收入、商品、客户、渠道、履约和成本 |
| 库存 | 连接预测、采购、销售、仓库和现金 |
| 指标 | 描述业务对象的状态和经营结果 |
| 决策 | 基于目标、数据、规则和约束产生经营动作 |

## 5. 文件编号规则

所有知识文件均放在仓库根目录，使用两位序号控制 GitHub 展示顺序：

| 序号范围 | 用途 |
|---|---|
| `00–02` | 首页、知识地图和基础术语 |
| `03–14` | 当前核心经营与 AI 产品知识 |
| `15–17` | 案例、来源笔记和工具资源 |
| `18–39` | 后续新增稳定方法论和专题 |
| `40–69` | 后续新增流程、案例和复盘 |
| `70–89` | 预留扩展区 |
| `90–99` | 贡献规范、模板和维护材料 |

编号只表达阅读顺序，不代表知识层级。调整内容时应尽量保持既有编号稳定，避免频繁改名导致引用失效。

## 6. 领域命名规则

序号之后继续保留稳定的英文领域名：

- `gm-`：跨模块经营总方法论。
- `market-`、`tiktok-kalodata-`：市场、品类与数据化选品。
- `product-`：产品开发、采购、物流和库存。
- `growth-`：内容、达人、广告、Listing 和促销。
- `customer-`：客服、评价、会员和复购。
- `data-`：指标、BI、成本、利润和现金流。
- `organization-`：团队、协同、年度规划和复盘。
- `tiktok-`：TikTok 端到端流程与专项方法。
- `ai-platform-`：系统架构、AI 能力和智能体。

## 7. 扩展原则

1. 一个文件只解决一个主要问题。
2. 同一概念只保留一个权威定义，其他文件通过链接引用。
3. 业务知识与工具操作分开，避免工具变化导致方法论失效。
4. 每个主题尽量包含流程、角色、指标、系统和 AI 五个部分。
5. 案例必须区分事实、判断、假设和建议。
6. 新增指标时写明公式、口径、数据源、频率和责任人。
