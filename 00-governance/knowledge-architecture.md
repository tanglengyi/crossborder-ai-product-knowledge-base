# 知识脉络与目录架构

本文件定义 V3.1 之后的长期结构。目标是避免“文件越来越多但彼此不连接”，并把跨境、电商、产业、产品、商业经营和 AI 统一到一套 BOS 中。

## 1. 当前版本

> **V3.1｜Commercial Engine + Strategy Maps 补齐版**

V3.1 已经完成两项关键补齐：

1. **商业中段**：客户研究、商业模式、定价、GTM、B2B 销售、售前 POC、交易合同回款和客户成功；
2. **总地图层**：国家市场、行业、产品系统、全球生态链和六张 BOS 总地图。

因此当前主要缺口已从“没有框架”转变为“缺少真实交易、客户和行业案例验证”。

## 2. BOS 总主线

```text
产业 / 国家
→ 客户
→ 问题
→ 价值
→ 产品 / 解决方案
→ 商业模式
→ 定价
→ GTM
→ 销售 / 交易
→ 交付
→ 客户成功
→ P&L / 现金流
→ AI 化
→ 复盘复制
```

跨境经营是该系统的全球化应用；产业研究是前端机会发现方式；AI Business OS 是后端规模化能力。

## 4. 六张总地图

知识库所有新增内容原则上都要能映射到至少一张总地图：

1. **产业地图**：产业、行业、价值链、利润池；
2. **地区地图**：中国城市产业节点与全球国家市场；
3. **产品地图**：Physical + Digital + Service + 产品线组合；
4. **增长地图**：品牌、内容、广告、平台、销售和渠道；
5. **生态链地图**：供应商、制造、品牌、平台、服务商、客户；
6. **AI Business OS 地图**：业务、系统、数据、知识、Workflow、Agent、决策。

总入口：[`../11-strategy-maps/six-master-maps.md`](../11-strategy-maps/six-master-maps.md)。

## 5. 商业引擎

Commercial Engine 是市场机会和经营结果之间的桥梁：

```text
Customer Research
→ ICP / JTBD / DMU
→ Value Proposition
→ Business Model
→ Unit Economics
→ Pricing / Packaging
→ GTM / Partner
→ Pipeline
→ Presales / POC
→ Proposal / Deal
→ Contract / Payment / Acceptance
→ Customer Success
→ Renewal / Expansion
```

该层统一放在 [`../10-commercial-engine/`](../10-commercial-engine/README.md)。

## 6. 产业、行业、品类、产品的层级

必须保持以下层级，避免概念混乱：

```text
产业
→ 行业
→ 品类
→ 产品
→ 产品系统
→ 商业模式
```

例如：

```text
智能制造
→ 机器人
→ 割草机器人
→ RTK 割草机
→ 设备 + App + 云 + AI + 服务
→ 硬件销售 + 配件 + 服务/订阅
```

## 7. 地区知识的组织方式

地区分两类：

### 中国城市产业节点

用于回答：哪里有产业、供应链、客户、企业和现场学习机会。

主要放在 `06-career-industry` 和 `07-cases-projects`。

### 全球国家市场

用于回答：产品进入哪个国家、客户是谁、渠道是什么、如何定价、履约、合规和盈利。

主框架放在 `11-strategy-maps/global-market-map.md`，具体国家案例后续放入案例库。

## 8. 五类知识资产

- **Framework**：可复用方法论；
- **Case**：真实公司、客户、产品、交易和失败案例；
- **Template**：访谈、报价、P&L、研究、谈判和复盘模板；
- **Project**：真实项目和模拟经营项目；
- **Insight**：事实、判断、假设、适用边界和下一步行动。

## 9. 内容成熟度

| 层级 | 标准 |
|---|---|
| L0 | 占位或零散信息 |
| L1 | 结构、定义、核心问题完整 |
| L2 | 流程、指标、检查表、模板可执行 |
| L3 | 有真实案例、数据、结果和复盘 |

V3.1 后不再把“新增更多框架”作为主要目标，优先把关键知识推进到 L3。

- 产品线 P&L。

## 11. 新内容准入规则

新增一篇文档前先问：

1. 它属于哪张总地图？
2. 它解决哪个 BOS 环节的问题？
3. 是 Framework、Case、Template、Project 还是 Insight？
4. 是否已经有同类权威文档？
5. 能否产生可执行动作或决策？
6. 有什么证据可以把它从 L1/L2 推进到 L3？

如果回答不清楚，优先补充已有文档，而不是新增孤立文件。
