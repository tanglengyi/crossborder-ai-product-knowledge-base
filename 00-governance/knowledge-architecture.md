# 知识脉络与目录架构

本文件定义知识库的长期目录、编号、内容层级与阅读路线。目标是解决“文件越来越多但关系不清晰、旧编号冲突、只有框架没有内容、跨境与 BOS 两套体系并行”的问题。

## 1. 当前版本判断

当前知识库建议定义为：

> **V2.1｜BOS 融合与知识架构重构版**

当前已经具备：

- 商业机会研究、市场、选品、供应链、增长、客户、数据、组织等经营基础模块；
- TikTok 跨境经营与 Kalodata 选品专题；
- AI 电商平台与智能体能力设计；
- B2B 外贸独立站与工厂出口增长方法；
- BOS 顶层经营主链路；
- 个人职业迁移、行业选择与中国智能制造出海方向。

当前尚未形成完整内容的部分包括：

- 客户与消费者研究；
- 商业模式、定价与交易设计；
- 合同、谈判、认证与跨境风险；
- 国家市场地图与行业地图；
- 解决方案、售前、POC 与 B2B 渠道经营；
- 标准化项目库、洞察库与经营指标库。

因此，当前不是 V3.0，也不只是原来的 V2.0，而是完成顶层融合后进入内容补齐阶段的 V2.1。

## 2. 知识库总主线

知识库以后统一按照 BOS 经营闭环组织：

> **行业与战略 → 客户与市场 → 产品与解决方案 → 商业模式与定价 → 渠道与销售 → 交付与客户成功 → 财务与现金流 → 组织与治理 → 增长与资本 → AI 与 Agent**

跨境业务作为经营系统中的重点应用场景：

> **国家市场 → 客户需求 → 产品选择 → 供应链 → 准入认证 → 渠道获客 → 报价交易 → 履约售后 → 利润现金流 → 复盘复制**

个人职业成长作为 BOS 的个人应用：

> **产品交付 → 解决方案与售前 → 商业化经营 → 业务拓展 → 产品线经营 / 创业**

## 5. 内容完整度标准

每个模块不以“已经有标题”为完成，而以四级成熟度管理：

- **L0｜占位**：只有标题或零散提纲；
- **L1｜框架**：定义、问题和结构完整，但缺案例与工具；
- **L2｜可执行**：包含流程、指标、检查表或模板；
- **L3｜已验证**：有真实案例、数据、结果和复盘。

V2.1 的目标是：核心经营模块至少达到 L1，其中商业机会、市场、选品、供应链、增长、数据与 AI 达到 L2。

## 7. 使用规则

1. 新专题先确定所属经营环节，再决定文件编号；
2. 一篇文档可服务多个模块，但必须确定一个主归属；
3. 框架必须逐步补充案例、指标、模板和适用边界；
4. 事实、判断和假设分开记录；
5. 每次结构性调整同步更新 README、Roadmap、MkDocs 和 Release Notes；
6. 批量重命名必须建立旧路径迁移表，避免历史链接失效。
